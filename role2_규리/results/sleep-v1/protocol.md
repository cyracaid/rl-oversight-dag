# 수면 기록 2박 검토 재생 기준

2026-11-23에 실제 평가 전에 고정했다. 참가자마다 같은 기록에서 서로 다른 두 밤을 열고, 그 밤에서 발견한 입력 오류만 고친다고 가정한다. 수면시간·효율·불규칙성 결론 중 원래 계산 결과와 달라진 개수(0~3)가 주 지표다. 기존 코드의 계산식과 야간 품질 점수를 재사용한다. [기존 재생 코드](../../../experiments/cross_record_replay.py)

- **기준선**. 합성 점검을 제외하고 먼저 전체 패널로 기존 단일 밤 재생의 참가자·박수와 가시적 오류·2박 예산의 품질 규칙 평균을 재계산한다. 기존 기록은 사용 2,652박, 237명, 10박 이상 196명, 평균 0.002개(품질 포함 4개 결론)다. 차이는 집계로 저장한다. 다른 코호트는 명시적으로 표시한다.
- **개발·평가**. 비식별 참가자 코드의 SHA-256에 고정된 문자열을 더해 개발 20%·평가 80%로 배정한다. 같은 참가자의 모든 날짜·조건은 같은 쪽에 둔다. 개발 쪽 집계는 계산 점검용이고 주 판정은 평가 쪽에만 적용한다. 이미 살펴본 코호트를 다시 쓰면 같은 코호트 내 평가다.
- **포함 기준**. 기존 계산을 통과한 10박 이상, 정수 달력 일자, 참가자·일자당 한 건, 적어도 한 쌍의 실제 연속 날짜가 필요하다. 중복 일자 참가자는 제외하고 집계한다. 누락된 날짜를 건너 연속이라고 세지 않는다.
- **오류 주입**. 정상, 단발, 연속 이틀을 비교한다. 모든 가능한 한 밤 또는 연속 이틀 창마다 같은 입력 종류·방향으로 시각을 바꾼다. 네 가지 사전 지정 변형은 취침 −12시간, 일어남 +12시간, 입면 +60분, 깸 −60분이다. 앞의 두 가지는 AM/PM 오기, 뒤의 두 가지는 더 작은 시각 편향을 가정한 민감도 조건이다. 비율·세션 길이는 현실에서 추정한 값이 아니다. 계산 불가능한 창은 네 정책 모두에서 제외하고 변형별 제외 수를 기록한다. 실제 입력 세션 식별자가 없으므로 연속 날짜를 한 세션의 대리로 쓴다.
- **정책**. 무작위 2박, 기존 품질 점수 상위 2박, 품질 점수 합이 가장 큰 달력상 연속 2박, 첫날에 오류를 발견하면 인접 날짜를 우선하는 정책을 비교한다. 마지막 정책은 기존 품질 규칙과 첫날이 같고, 미발견이면 두 번째 날도 같다. 인접 후보가 여럿이면 품질 점수가 높은 날을 고른다. 모든 정책의 무작위 순서와 동점 우선순위는 참가자별 고정 난수로 생성하고 오류 주입 위치와 독립적으로 공유한다. 동점 사례 비율도 남긴다. 정책은 점수·날짜와 이미 열어 본 첫날의 발견 여부만 쓴다.
- **분석**. 각 참가자의 유효한 창과 변형에 걸쳐 평균을 낸 뒤 참가자에 동일 가중치를 준다. 주 비교는 평가 참가자의 연속 이틀 주입에서 연속 선택 − 품질 규칙이다. 보조 비교는 첫날 피드백 − 품질 규칙이다. 참가자 쌍 단위로 10,000회 재표집한 95% 구간의 상한이 0보다 작으면 해당 조건에서 개선으로 판정한다. 품질 규칙 통과 여부(네 번째 결론), 검토 전 기준, 오류 종류별 잔여 개수도 별도로 기록한다.
- **사람 정정**. 비식별 일자별 정정 전·후 패널이 같은 참가자·날짜로 연결될 경우 별도 표를 산출한다. 분석 가능한 날짜 집합이 일치하는 참가자만 포함한다. 오류 발견은 연 기록의 계산 입력이 정정본과 실제로 다른 경우로 정한다. 정정 패널은 해당 범위의 모든 확인된 수정을 포함해야 한다. 이것은 주입한 오류를 맞히는 평가와 구분한다. 참가자 결론의 독립적인 임상 정답은 별도로 필요하다.
- **검토시간**. 실제 걸린 분과 수정 결과가 있는 검토자 비교는 재생에서 개선된 조건을 정한 뒤 수행한다. 컴퓨터 실행시간이나 모델이 연 밤의 수를 사람의 검토시간으로 바꾸지 않는다.
