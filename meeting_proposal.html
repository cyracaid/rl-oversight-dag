该先审哪一项？ / Which item first? / 어느 항목 먼저?

STA3145 Reinforcement Learning · Group project · 2026-11

Sleep data: 1-year EMA with Maia ten Brink (Stanford Psychophysiology Lab) · Application: SciForge (Zhangyang Gao, AI4Science, Shanghai AI Lab)

0一句话

AI 帮实验室洗日记、标文献、跑分析。结果互相依赖：时间反了，潜伏期错，效率错，结论不可信。

人不可能全查。我们用 RL 学一个只读建议器：下一步审哪个节点，让更少错误走到结论。

机器不盖章 只读排序 人点裁决才有收据

1为什么是真的

我们实验室睡眠日记：13,990 条 / 237 人。人只改了 75 处（0.54%）。

这 75 处 76% 是同一种错（order_error，p<0.0001）。

这 76% 是什么、不是什么。这 75 处是参与者填表时的录入错误，不是 AI 犯的错；发现它们的是规则引擎（M1–M7），其中 84 行还被自动改正。57/75 = 76%（8 行无标签；27 条双人共识 / 48 条单人）。p<0.0001 说的是「错误高度集中在同一类型」，不是「模型很差」，也不是模型之间的比较。样本只有 75 条、单实验室——它是描述性动机，不是效应量。

错不会待在原地：时间错 → 潜伏期错 → 效率错 → 结论错。

「审多少」不如「审什么」。预算只有一点点，花在 76% 那种错的上游更值。

2走过的弯路

第一版做成逐条 bandit。阈值赢了 Q-learning（2.81 vs 3.38）。

原因：逐条审把依赖图压平了，RL 没东西可学。76% 一种错，最优策略退化成 if 规则。

这个失败没藏，它是重构的理由。

3重构：下一个审哪个

证据画成有向图。智能体每步选一个节点审。审对了下游跟着变。

真 MDP：状态有图和剩余预算，奖励只在最后。

前端 划线提问 / 日记行审阅 → 审阅痕迹（不是收据） ↓ 审阅层 信念贪心 / GNN / 阈值 建议器 → 「先审这几个」（只读） ↓ 人点「裁决」 后端 SciForge 证据 DAG + 收据 → 机器不盖章，append-only

0One sentence

AI already cleans diaries, labels papers, runs analyses. Outputs depend on each other: a flipped time becomes a wrong latency, a wrong efficiency, an untrustworthy conclusion.

A human cannot check everything. We train a read-only RL suggester: which node to review next, so fewer errors reach the conclusion.

Machine never stamps read-only ranking receipt only on human verdict

1Why this is real

Our lab's sleep-diary data: 13,990 records, 237 people. Humans corrected only 75 (0.54%).

Those 75 are not scattered — 76% are the same mistake (order_error: times in the wrong order).

What 76% is, and is not. The 75 are participant data-entry mistakes, not AI errors. A rule engine (M1–M7) detects them, and 84 rows were auto-corrected. 57/75 = 76% (8 unlabelled; 27 double-coded by consensus, 48 single). p<0.0001 says errors cluster in one type — not that the model performs badly, and not a model comparison. n = 75, one lab: a descriptive motivation, not an effect size.

The mistake does not stay put. Wrong time → wrong latency → wrong efficiency → wrong conclusion.

"What to review" matters more than "how much." The budget is tiny. Spend it upstream of the 76% type.

2The detour (honest)

First version: a bandit, one item at a time. Result: a simple threshold beat Q-learning (2.81 vs 3.38).

Why? Per-item review flattens the graph. RL had nothing non-trivial to learn. With 76% one type, the best policy collapses into an if-rule.

We did not hide this failure. It is the reason for the reframe.

3Reframe: which node next?

Draw the evidence as a directed graph. The agent walks it and picks one node to review. A good review changes the downstream.

This is a real MDP: the state has the graph and remaining budget; the reward arrives only at the end.

Front end highlight-and-ask on diary rows / code / claims → review traces (not receipts) ↓ Review layer belief greedy / GNN / threshold → "review these first" (read-only) ↓ human clicks "verdict" Back end SciForge evidence DAG + receipts → machine never stamps, append-only

DQN degenerates to random — sparse terminal reward cannot feed a value function. Policy gradient is the right tool here.

8OpenAI's two benchmarks

HealthBench: physician rubrics + worst-of-n + consensus/hard split.BioBasicsBench: raw wet-lab evidence + error detection + "evidence is not enough." Failure mode: assumption overrides a control — same species as our 76% order_error.

Add: budget, dependency graph, penalty delayed to the conclusion. They did not build this.

0한 문장

AI가 이미 일기를 정제하고, 문헌에 라벨을 달고, 분석을 돌립니다. 출력은 서로 의존합니다: 시간이 반대로 쓰이면 잠복기가 틀리고, 수면 효율이 틀리고, 결론이 믿을 수 없게 됩니다.

사람이 전부 확인할 수는 없습니다. 강화학습으로 읽기 전용 제안기를 학습합니다: 다음에 어떤 노드를 검토할지, 결론에 도달하는 오류를 줄이기 위해서.

기계는 도장을 찍지 않음 읽기 전용 순위 사람이 판정해야 영수증

1왜 진짜 문제인가

우리 실험실 수면 일기: 13,990 기록, 237명. 사람이 고친 것은 75건(0.54%)입니다.

그 75건은 흩어져 있지 않습니다 — 76%가 같은 실수(order_error: 시간 순서 반대)입니다.

76%가 무엇이고 무엇이 아닌가.그 75건은 참가자가 입력할 때 낸 실수이며 AI의 오류가 아닙니다. 규칙 엔진(M1–M7)이 찾아내고 84행은 자동 수정되었습니다. 57/75 = 76% (8건 무라벨, 27건 합의 · 48건 단일). p<0.0001은 오류가 한 유형에 몰려 있다는 뜻이며, 모델 성능이 나쁘다는 주장도 모델 간 비교도 아닙니다. n=75, 단일 실험실: 서술적 동기이지 효과 크기가 아닙니다.

실수는 제자리에 머물지 않습니다. 시간이 틀리면 → 잠복기가 틀리고 → 효율이 틀리고 → 결론이 틀립니다.

"얼마나 검토하느냐"보다 "무엇을 검토하느냐"가 중요합니다. 예산은 작습니다. 76% 유형의 상류에 쓰는 것이 값집니다.

2돌아간 길 (솔직하게)

첫 버전은 밴딧이었습니다. 결과: 간단한 임계값이 Q-러닝을 이겼습니다 (2.81 vs 3.38).

이유: 항목별 검토는 그래프를 평평하게 만듭니다. 76%가 한 유형이라 최적 정책은 if-규칙으로 무너집니다.

이 실패를 숨기지 않았습니다. 재구성의 이유입니다.

3재구성: 다음 노드는?

증거를 방향 그래프로 그립니다. 에이전트가 걷고 노드를 하나 골라 검토합니다. 좋은 검토는 하류를 바꿉니다.

진짜 MDP입니다: 상태에 그래프와 남은 예산, 보상은 마지막에 옵니다.

Front end 일기 행 / 코드 / 주장에 하이라이트-질문 → 검토 흔적 (영수증 아님) ↓ Review layer 신념 그리디 / GNN / 임계값 제안기 → "이것 먼저 검토" (읽기 전용) ↓ 사람이 "판정" 클릭 Back end SciForge 증거 DAG + 영수증 → 기계 도장 없음, append-only
