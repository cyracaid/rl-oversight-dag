## 1. 六篇关键论文详读

### 1.1 SLTD — Sequential Learning-to-Defer
- **标题**：Learning-to-defer for sequential medical decision-making under uncertainty
- **arXiv**：2109.06312（2021）
- **定位**：第一个把 L2D 建模成 **model-based RL** 的工作。作者明确批评现有 L2D "myopic""defer at every instance independently, ignoring long-term impact"。
- **核心**：在每个时间步决定"现在 defer 还是下一时间步再 defer"，量化 **delayed deferral 的影响** 和 **propagated uncertainty（传播的不确定性）**。用非平稳 MDP 建模疾病动力学。
- **→ 对你们**：这正是团队声称的差异点 #1"漏掉错误的代价到达得很晚，要等它扩散到结论后才出现"。**别人 2021 年已经把这个"延迟才算 RL 问题"的框架做出来了。**

### 1.2 Online Decision Deferral under Budget Constraints
- **arXiv**：2409.20489（2024）
- **定位**：把在线 L2D 建模为 **双臂 contextual bandit + 预算约束**。区分 full-information 与 bandit 反馈两种 partial feedback 模型。预训练模型固定、任务流式到达、分布可能漂移。
- **代码**：`github.com/tsuehr/OnlineLearningToDeferWithKnapsack`
- **→ 对你们**：与团队的状态/行动/预算设定几乎同构。差异点 #2"在预算约束下在线决定审查哪些"**直接命中**。

### 1.3 BACID / OLBACID — Learning to Defer in Congested Systems
- **arXiv**：2402.12237（2024）
- **场景**：内容审核。AI 分类 + 决定哪些任务进入人工审查队列 + 从队列调度给审查者。
- **关键**：人类反馈的延迟是**内生的**（队列拥堵造成），不是外生假设。这是比团队设定更强的延迟模型。在线学习版 OLBACID 达成 $\tilde{O}(K\sqrt{T\ln T})$ regret。
- **→ 对你们**：延迟 + 容量约束 + 在线，三者同时覆盖。

### 1.4 KL-PBD — To Defer or Not to Defer? Online Learning with LLMs and Congested Experts
- **arXiv**：2610.15128（2026-10）
- **作者**：Saketos, Reveillard, Proutiere, Dalleiger, Xiao
- **核心**：在线、**选择性 + 延迟反馈**（只 defer 的 query 才被标注，且标注又被队列延迟）、容量受限专家。用 KL 下置信界学习未知的置信度可靠性。gap-dependent $O(K\log T)$、最坏 $\widetilde{O}(\sqrt{KT})$ regret，含下界。真数据：GSM8K / NuminaMath / MedMCQA + Qwen。
- **→ 对你们**：2026 年 10 月刚出，是最新的"延迟惩罚 + 选择性反馈 + 预算"完整解。

### 1.5 FALCON — Fatigue-Aware Learning to Defer via Constrained Optimisation ⚠️ 最致命
- **arXiv**：2604.00904（2026-04，v2 2026-04-03）
- **作者**：Zhang, Nguyen, Rosewarne, Wells, Carneiro
- **核心**：
  - 批评现有 L2D 假设**人类表现恒定**，忽略疲劳导致的表现退化。
  - 用**心理学的疲劳曲线**显式建模随工作量变化的人类表现。
  - 把 L2D 形式化为 **Constrained MDP (CMDP)**，**状态 = 任务特征 + 累积人类工作量**。
  - 在"人类-AI 合作预算"约束下用 **PPO-Lagrangian** 优化准确率。
  - 提出 **FA-L2D 基准**，系统变化疲劳动力学（近静态 → 快速退化）。
  - 结果：跨数据集、跨 coverage 全面超 SOTA L2D，并能**零样本泛化到未见过的、不同疲劳模式的专家**。
- **→ 对你们**：这是**几乎逐条对应你们项目**的论文：

  | 团队设定 | FALCON 对应 |
  |---|---|
  | 状态含"审查者疲劳度" | 状态含"累积人类工作量"（疲劳曲线建模） |
  | 固定审查预算 | "人类-AI 合作预算"约束 |
  | 用 RL（bandit / Q-learning） | CMDP + PPO-Lagrangian（比你们的 bandit 更强） |
  | 审查者疲劳时准确率下降 | 疲劳曲线直接建模准确率随工作量退化 |

  **团队项目 = FALCON 的 CIFAR-10 玩具弱化版。** 这是必须面对的事实。

### 1.6 Learning to Defer: A Survey
- **出处**：Zenodo 2025-12（预印本，标注"under review, not peer-reviewed"），Oxford ORA
- **结构**：四分支——methodological frameworks / optimization & theory / task generalizations / real-world adaptations。
- **关键**：明确把 **sequential settings**（顺序设定）和 **workload/budget control**（工作量/预算控制）、**dynamic expert pools** 列为已成体系的分支。
- **→ 对你们**：这篇综述的存在本身说明"顺序 + 预算"的 L2D 已经是综述级话题，不是团队文档暗示的空白。

### 1.7（背景线）延迟反馈 bandit
- **Joulani, György, Szepesvári — Online Learning under Delayed Feedback, ICML 2013**：确立结论——随机 bandit 里延迟只造成**加性** regret 惩罚，对抗 bandit 里造成**乘性**惩罚。之后 2018–2026 大量后续（MABDAAF、GLB delayed、Lipschitz delayed、best-of-both-worlds delayed 等）。
- **→ 对你们**："延迟惩罚"在 bandit 文献里是标准设置，不是你们的新颖点。

## 4. 团队项目的真实定位（诚实版）

1. **问题本身不新。** "contextual bandit + 预算 + 延迟惩罚" 有完整成熟文献。
2. **算法不新。** bandit / Q-learning 弱于 FALCON 的 PPO-Lagrangian 与 KL-PBD 的 KL-LCB。
3. **唯一可能的立足点**：把审查调度问题放到**具体的研究证据链领域**，并回答一个别人没回答的实证问题——**"真实研究数据里，错误是否真的按类型聚集、并沿依赖关系扩散到结论？"** 如果聚集假设在你们自己的睡眠/标注数据上不成立，那这也是一个诚实且有价值的结论。
4. 团队文档第 6 节"贡献在于清晰的问题表述 + 受控对比"的自我定位，在**补齐上面文献后**才是可辩护的。否则"清晰表述"会变成"不知道已有表述"。
