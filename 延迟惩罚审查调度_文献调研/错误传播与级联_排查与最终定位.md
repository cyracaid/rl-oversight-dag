# 错误传播与级联：文献排查 + 最终定位

> 更新：2026-11-08
> 排查目标：确认"错误沿依赖图/证据链往下游传播"是否已有定型结论，以及"传播 + 预算审查调度"这个组合是否已被人做过。

---

## 1. 排查结论（一句话）

"错误沿依赖图往下游传播、到结论才暴露"这个**结构**，在至少五个领域已有大量工作；但"**传播结构 + 有限人工审查预算 + 学习该审哪个节点**"这个**组合**，没有找到直接先例。你们最后一点空间就在这个组合上，且条件仍是：必须把传播做成真结构 + 用真实数据验证。

---

## 2. 五条已有的"错误传播"脉络

### 2.1 HCI / 数据质量（概念层）
- **Data Cascades（Sambasivan et al. 2021, CHI）**："Everyone wants to do the model work, not the data work"。53 名从业者访谈，定义"data cascades"= 数据问题引发的、随时间复合的下游负面效应。性质：**opaque / delayed / invisible**，92% 发生率，可经早期干预避免。
- → 这是你们 §2"事实二"（错误被下游复用、危害到结论才暴露）的**概念级原话**，但它是定性 HCI 研究，**不是**学习式审查调度算法。

### 2.2 NLP 标注流水线（最接近你们的"条目复用"结构）
- **Finkel et al. 2006**："Solving the Problem of Cascading Errors: Approximate Bayesian Inference for Linguistic Annotation Pipelines"。NLP 流水线每阶段错误传播/复合，建模为 **Bayesian 网络**（每阶段一个变量），近似推断。
- → 结构接近（条目间依赖 + 错误传播），但目的是**流水线架构**（传播分布而非 1-best），不是"预算下审查哪些条目"。

### 2.3 ML 流水线 / 复合 AI 系统（诊断与韧性层）
- **Nushi et al. 2017（AAAI）** + **Pandora（2018, Microsoft）**：integrative ML 系统错误诊断/归因，组件间"non-monotonic error propagation"。
- **Compound AI System Reliability（ICML 2026, arXiv:2610.02503）**：150 起生产事故 → 23 类故障；级联错误跨组件边界传播；circuit breaker 减 89% 传播、output quality gate 拦 73% 静默退化。
- → 描述 + 韧性工程，无学习式审查调度。

### 2.4 LLM 多智能体 / 推理（最新的"依赖图传播"）
- **From Spark to Fire（arXiv:2603.04474, 2026-03）**：把 LLM 多智能体协作抽象为**有向依赖图**，给"早期风险准则"刻画放大风险；注入单个原子错误 → 大面积失败；提出 genealogy-graph 治理层（消息层插件）。
- **Cascading Failure Amplification in Multi-Step LLM Reasoning（ICML 2026）**：定义 Amplification Factor (AF)，发现后步错误危害更大；**"allocate verification compute"** 的干预——跨验证把 cascade 从 24%→9%。
- **SAFE（arXiv:2604.01993）**：逐步证据接地验证，错误传播前拦截。
- → 这些**已经有"沿依赖图传播 + 在哪里投入验证算力"**的味道，最接近你们。但验证者是 LLM/符号器，不是**预算约束下的人类专家审查**。

### 2.5 你们的真实领域（研究数据标注本身）
- **Sequence database network（PMC9677457, 2022）**：生物信息学序列库，明确把 **annotation propagation** 列为错误主要来源，网络视角检测/纠正错误。
- **DN-ILDL（arXiv:2405.16474, 2024）**：label-dependent noise——**明确用 cat/dog 举例**"狗易因视觉相似被标错"。
- → 你们 §2"事实一"（错误按类型聚集、猫狗混淆）在 label-noise 文献里是**已知概念**（label-dependent noise）。你们的睡眠/文献标注数据正属于这一支。

## 3. 最终定位（三股文献拼起来）

| 你们的组件 | 是否已有 | 代表 |
|---|---|---|
| 疲劳 + 预算 + RL 审查 | ✅ 已有 | FALCON(2604.00904) |
| 在线 + 预算 + bandit 审查 | ✅ 已有 | Online Deferral Budget(2409.20489) |
| 延迟 + 选择性反馈审查 | ✅ 已有 | KL-PBD(2610.15128)、BACID(2402.12237) |
| 顺序 + 长期后果 defer | ✅ 已有 | SLTD(2109.06312) |
| 错误按类型聚集 | ✅ 已知概念 | label-dependent noise(2405.16474)、CIFAR-10H |
| 错误沿依赖图传播到结论 | ✅ 已有结构 | Finkel 2006、From Spark to Fire(2603.04474)、Data Cascades |
| **传播结构 + 预算 + 学习该审哪个节点** | ❌ **未找到直接先例** | —— |

**你们唯一站得住的定位：** 把"证据链依赖图上的错误传播"和"预算约束下学习式审查调度"接起来，用在真实研究标注数据上。这是组合新颖性，不是任何单一组件的新颖性。

---

## 4. 必须做的三件事（否则不成立）

1. **传播做成真结构**：条目间有依赖关系，错误沿依赖图往下游传（不是现在 §4 的"结尾惩罚 + 同类型加罚"弱代理）。这是你们与 FALCON/bandit 系列唯一不可否认的分界线。
2. **基线含"按类型校准阈值"**：照 Online Deferral Budget 的 BestReject 思路，并诚实报告学习策略在哪些条件下不更好（若不更好，负结果本身有价值）。
3. **真实数据验证聚集假设**：用你们手头睡眠/文献标注数据，先验"错误是否按类型聚集 + 是否沿依赖传播"是否成立。若这条假设都不成立，整个项目的前提就塌了——这是最该先做的实验。
