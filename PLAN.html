3. 五个人，各自交什么

WP0

P1 · 组长 / 协议

唯一职责：让所有人的数字可比
  • eval.py：唯一的 recall / CI 实现
  • 表头模板 + 种子协议 + 配对规则
  • 退回没有 CI 或没有脚本路径的表
验收：别人 import 你的 eval，不复制你的代码。D2 前定死。
WP1

P2 · 策略梯度

回答一个问题：RL 输在表示，还是输在信用分配
  • belief / static / observed / belief greedy 四路
  • 5 种子 × 200 held-out × 配对 bootstrap
  • 每种子数字全部公开，不报最好的那个
验收：一条命令出一张表；成立或不成立都算交付。
阻塞于：WP2 冻结。
WP2

P3 · 环境

卡点本人：环境一动，全部数字作废
  • 合成生成器打 tag 冻结
  • 定义迁移数据集的 item schema
  • 写 KAIST 适配器
验收：--dataset kaist 一条命令跑通；冻结后改环境 = 新版本 + 重跑全部表。
WP3 · WP4

P4 · 基线 / 对照

先调研，再实现两个；Option 2 时做诊断
  • 5 个候选：VOI、MCTS、BC、离线 RL、Transformer
  • 实现最便宜的两个，接同一 harness
  • 诊断：信用分配相关性、回报方差、四个干预
验收：一页对比表（fit/effort/risk）+ 两个能跑的基线。
WP5

P5 · 你 / 数据

唯一真正独立的活，但决定能不能 generalize
  • KAIST → GO → Manchester，逐个核实许可与字段
  • 打开真实文件，不看摘要
  • 数据不进 repo，只进聚合
验收：每行都有可验证的 license + 能跑的加载命令。
