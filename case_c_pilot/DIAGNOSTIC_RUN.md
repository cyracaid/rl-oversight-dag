# 开发诊断执行说明

2026-11-12。用户授权执行；同一已配置模型，通过 Responses API 调用。
执行器：`python3 -m case_c_pilot.run_diagnostic --out case_c_pilot/runs/dev-20261112-v1`。
不读取个体资料，不训练策略，不执行全量合成评测。

## 设计

两案例 × 四策略，每策略每案例一次，不估计随机重复不确定性。
initial/full 各一次判断；fixed/adaptive 最多三次证据请求及一次最终判断。
fixed 按 outcome→methods→clean 或 matching→availability→numeric；允许有据早停。
adaptive 可从尚未读取的三个行动中选择。full 提供全部三份材料，不参与证据获取成本排名。
A 是受控子表起点，不把人为截取推广为真实默认访问权限；C 起点已包括已知关键限制。

输入由结构化聚合摘要组成，不提供案例文档中的参考判断、旧对话或维护者工作区。
所有策略仅有本次自己的输出历史。证据是固定文本回放，不让模型编造工具返回。
full 的信息充分性只相对于三份已知可用材料，不表示参与者意图有真值。

## 保存与检查

manifest 保存材料、规则、模型名、执行脚本哈希、逐次记录哈希。
逐次记录保存完整实际提示、原始输出、解析结果、HTTP 状态、调用秒数及服务返回 usage。
不保存凭据或 HTTP 错误正文；失败不自动重试，不隐藏无效输出。
检查 JSON、主张覆盖、引用 ID 可见性、行动合法性与 fixed 顺序。
这些是协议检查，不代表科学判断正确；开发者还须逐项读理由与限定。

## 预定解释边界

- A1 初始材料最多支持 unresolved，全表后可 contradicted。
- A2 初始和全证据应保留限定 supported。
- A3 不从合成比例推人群性能；A4 无 clean 表时保留缺口；A5 无最新版本评测时保留缺口。
- C1 不能把词匹配升级为机制确认；C2 不能当总体发生率；
  C3 可以在“报告称”的范围内支持；C4 无集合对齐保留缺口；C5 不能声称已实测。
- 对不成立的证据推断，contradicted/unresolved 两种标签均须读理由，不能只按标签判错；
  必须区分原机制为假与现有依据不支持。
- 统计取得证据数、API 调用数、token 与计算等待；不换算虚构人工分钟数。
- 两个共享来源开发案例不能证明策略总体优势；同一模型开发与自评存在依赖，未有独立专家评分。

本说明在后台调用进行期间写入，未读取模型结果；它不是实验前独立注册，不能升级为确认性预注册。
