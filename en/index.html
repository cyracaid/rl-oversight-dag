Which item should a human review first?

Reinforcement learning for the review layer of a research evidence chain.

Sleep data: one year of EMA collaboration with Maia ten Brink (Stanford Psychophysiology Lab).
Application: SciForge, developed by Zhangyang Gao (AI4Science, Shanghai AI Lab).

Machine never stamps read-only ranking receipt only on human verdict

What we build

AI already cleans sleep diaries, labels papers, runs analyses. Its outputs depend on each other: a flipped time becomes a wrong latency, a wrong sleep efficiency, an untrustworthy conclusion.

A human cannot check everything. We train a read-only RL suggester: which node to review next, so fewer errors reach the conclusion.

The machine never stamps. The suggester is a read-only advisor. A review becomes a receipt only when a human records a verdict.

Why this is real

Our lab's sleep-diary data: 13,990 records, 237 people, from the one-year EMA collaboration with Maia ten Brink. Humans corrected only 75 of them (0.54%).

Those 75 are not scattered — 76% are the same mistake (order_error: times written in the wrong order; p < 0.0001).

The mistake does not stay put. Wrong time → wrong latency → wrong efficiency → wrong conclusion.

That is why "what to review" matters more than "how much." The budget is tiny. Spend it upstream of the 76% type.

The detour we took (honest negative result)

Our first version was a bandit: "review this item or not," one at a time. Result: a simple threshold beat Q-learning (2.81 vs 3.38).

Why? Per-item review flattens the graph. RL had nothing non-trivial to learn. With 76% one type, the best policy collapses into an if-rule.

We did not hide this failure. It is the reason for the reframe.

Reframe: from "review this item?" to "which node next?"

Draw the evidence as a directed graph. The agent walks the graph and picks one node to review. A good review changes the downstream.

This is a real MDP: the state has the graph and the remaining budget; the reward arrives only at the end.

Front end highlight-and-ask on diary rows / code / claims → review traces (not receipts) ↓ Review layer belief greedy / GNN / threshold → "review these first" (read-only) ↓ human clicks "verdict" Back end SciForge evidence DAG + receipts → machine never stamps, append-only

Math skeleton (the RL-course main course)

1. Causal propagation (intervention on a DAG). \(X_v \in \{0,1\}\) (1 = correct). For an edge \((u,v)\) with weight \(w_{uv} \sim U(0.5, 1.5)\):

\[ P(X_v = 0 \mid X_u = 0) = 1 - \exp(-\lambda\, w_{uv}), \quad \lambda = 0.8 \]

Reviewing \(v\) = do\((X_v := 1)\). Causal intervention, not correlation.

2. MDP. State = graph knowledge + remaining budget. Action = next node (or stop). Reward \(r_T = -\#\text{sink errors}\). \(\gamma < 1\).

3. CMDP Lagrangian. \(\max_\pi \min_{\lambda \ge 0} J(\pi) + \lambda\,(B - C(\pi))\). Main method today is GNN + fixed-budget REINFORCE; dual-critic CMDP is in progress.

4. Adaptive greedy on a belief. A particle filter tracks which nodes are likely wrong; each step reviews the node with the largest expected drop in conclusion errors, then updates the belief with what the reviewer found. On N=500 scale-free graphs it goes from 81 to 12.8. The same rule on the true errors (oracle) reaches 3.6, but no real policy can see the truth.

5. Information-gain reward (in the design, not yet run). \(R = \alpha\, \Delta H_v - \beta\, \mathrm{Cost}(v)\)

6. Policy gradient (main method). \(\nabla_\theta J = \mathbb{E}[ \nabla_\theta \log \pi_\theta(a_t \mid s_t)\, A_t ]\)

GNN scorer: \( h_v = \tanh(W_{\text{self}} x_v + W_{\text{neigh}} \frac{1}{|N(v)|}\sum_{u\in N(v)} x_u ) \)

7. Worst-of-n. One unreviewed error can invalidate a conclusion (HealthBench). Worst of 3 seeds: noise 5.20, oracle 0.80.

The table above uses seeds 1–20, which turned out to be easy graphs. On 200 unseen graphs: threshold 1.41, structural greedy 1.45, belief greedy 1.14, GNN 1.56. The deployable belief greedy beats every learned policy (GNN − belief greedy = +0.42 ± 0.15), and giving the GNN its review outcomes did not help.

DQN degenerates to random — a sparse terminal reward cannot feed a value function. Policy gradient is the right tool here.

V1 as a per-item bandit lost to a threshold (2.81 vs Q-learning 3.38). That failure is why we reframed.

Do not keep tuning the scheduler. Invest in the confidence signal. We located where the remaining error lives: the predictor, not the policy.

Worst of 3 seeds: normal 1.95 / noise 5.20 / oracle 0.80. A noisy signal hurts the tail more than the mean.

Related work

HealthBench (2025-05) taught us to evaluate with meaningful, trustworthy, non-saturated rubrics and worst-of-n reliability.

BioBasicsBench (OpenAI + Ligo, 2026-11-06) asked whether an agent can read raw wet-lab evidence and know when it does not support a conclusion. Top model 66.7%. Failures: assumption overrides a control; contradictory observations discounted; miscount. Our 76% order_error is the same species.

Learning to defer: Mozannar & Sontag ICML 2020; FALCON arXiv:2604.00904; SLTD arXiv:2109.06312; Reid et al. arXiv:2409.20489; KL-PBD arXiv:2610.15128; Oversight arXiv:2606.08919. Cascades: Data Cascades CHI 2021; Finkel EMNLP 2006; From Spark to Fire arXiv:2603.04474. Budget + node selection: WS-option arXiv:2502.05537; Mattick arXiv:2310.00112.

We adopt: meaningful / trustworthy / non-saturated; worst-of-n; partial-credit receipts; error detection as a first-class skill; "evidence cannot support this conclusion" as an action.
We add: budgeted sequential review over a dependency graph — they did not build this.

Landing in SciForge

SciForge already has an evidence DAG, human-review receipts, and an audit layer. This project adds a review-priority suggester on top, changing no record-keeping rules.
