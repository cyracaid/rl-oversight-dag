| ④ Conclude | 4 validity/quality verdicts | wrong verdict | 0.05–0.35 | **sinks: reward only counts these** |

**Term card (bottom-right small box, or say it aloud)**

| Term | One line |
|---|---|
| Node | One output value of one pipeline stage: raw field, derived value, metric, or verdict. 21 in total. |
| Hidden error | Whether the node's **own** (base) value is wrong. Unobservable; the policy sees type, confidence, sink reach, reviewed flag, belief. |
| Processing-stage node | Any of the four layers. The conclusion layer is the sink layer, and there can be several sinks (four here). |
| State | Per node {type, confidence, sink reach, reviewed, P(base), P(error)} + remaining budget. H = B, γ = 1. |

**Footline that closes the teacher's question**
> Conclusion nodes can hold their own base error; review clears only that node's own error and recomputes downstream.

## New slide C — Three requirements map onto one MDP

**Title**  `Three requirements, one MDP`
**Subtitle**  `Not three literatures side by side: three components that feed each other.`

| Requirement (literature) | Component in our method | Anchor |
|---|---|---|
| Hand the decision back to a human (learning-to-defer) | Action = review one unreviewed node; inspection may miss (p_catch = 0.9); terminal reward = −residual sink errors | `PROPOSAL_COURSE_KO.md §4` reward row; `IMPLEMENTATION_SPEC.md §2.3` |
| Allocate reviews under a budget (budgeted bandit) | State carries `budget_left`; finite horizon H = B; episode ends when the budget is spent | `PROPOSAL_COURSE_KO.md §4` state row |
| Errors accumulate downstream (error cascade) | Dependency DAG (parents, sinks) + hidden-error belief (P(base), P(error)) + transition: repair clears base, downstream recomputed | `IMPLEMENTATION_SPEC.md §2.2/§2.3/§2.5` |

**Necessity, in four lines (replaces "nobody has done it")**

1. **Deferral alone** decides per item whether to escalate. Without the graph it cannot tell that fixing one upstream row saves several downstream conclusions, and cannot rank what to check first.
2. **Budget allocation alone** treats items as independent arms. Without a hidden-error belief it cannot rank by *error probability × downstream impact*.
3. **Error cascade alone** shows errors accumulate but never answers *which link a time-limited human should inspect*.
4. **Together**: the graph supplies candidates and impact weights, the belief supplies the ranking, the budget supplies horizon and stopping. **Remove any one and the ranking itself is undefined.**

## Baseline numbers on the real graph (recomputed after a bug fix)

The `hub` baseline was broken: `real_pipeline_graph.py` credited every edge to one node because of a stale loop variable. Fixed, rerun, 8 seeds, budget 8 of 21:

| Policy | Mean residual sink errors |
|---|---:|
| no review | 2.12 |
| random | 1.88 |
| hub (child count) | 1.88 |
| **confidence threshold 0.5** | **0.50** |

Two scope facts to say out loud:

- The main synthetic setting uses **16 reviews**; the real DAG uses **8 of 21**. Do not let the two numbers look like a contradiction.
- At N=21 only **heuristics** are run — belief greedy is not run at this size (`PROPOSAL_COURSE_KO.md` section 6). So 0.50 is a heuristic bar, not a greedy-vs-learned comparison.

Two consequences for the talk:

- Do **not** cite the old `hub = 1.75`; it came from the bug.
- Confidence thresholding is a **strong** baseline on the real graph (0.50 vs 2.12). Say so before the teacher does: it is exactly why learned policies must be compared against a strong baseline, and it sets the bar any improvement claim has to clear. Degree-based selection carries no benefit here.
